# LocalU — 局域网「挂载端 + 移动端」文件管理服务 需求规格说明书

> 文档版本：v0.1
> 关联产物：原型稿 `localU.ini`（挂载端/移动端双端职责定义）；界面基线 `app/` 当前 Flutter UI（macOS / iOS 截图）
> 适用代码库：`https://github.com/changpinggou/localsend`（Flutter app + Rust 核心）
> 阅读对象：产品 / 客户端 / 服务端 / 安全 / 测试工程师

---

## 0. 术语表

| 术语       | 含义                                                                                                          |
|------------|---------------------------------------------------------------------------------------------------------------|
| **挂载端** | 桌面端（macOS / Windows / Linux），作为文件服务方（Host / Server）                                            |
| **移动端** | iOS / Android，作为文件浏览方（Client / Explorer）                                                             |
| **挂载点** | 桌面端暴露给移动端可访问的存储根，例如 Windows 的 `D:\`、macOS 的 `/Volumes/ExternalSSD`                        |
| **会话**   | 一次"挂载端 ↔ 移动端"已建立 TLS 通道并完成 PIN 配对的连接，与现有 LocalSend 的"会话"概念一致                  |
| **远端路径** | 移动端视角下的"挂载端上的路径"，形如 `D:/Photos/2026/IMG_0001.jpg`，**必须**经服务端解析为绝对路径并校验 |
| **白名单**| 挂载端设置中允许暴露给移动端的根路径集合，缺省仅包含外接驱动器                                               |
| **CRUD**  | 文件 / 目录的 Create（建）、Read（读）、Update（改 = 移动/重命名）、Delete（删）                              |

## 1. 项目背景

### 1.1 现况

LocalSend 当前定位是"无中心、端到端、局域网直传"的 AirDrop 替代品。截图所示的 macOS / iOS 接收页是当前主界面：

- 顶部：标题「LocalSend」+ 右上角「历史」与「关于」入口
- 主体：设备品牌 logo（青色虚线圆环）+ 设备别名（例如 `常平zego-mac`、`常平的iphone17pro`）
- 主操作：「通过链接接收」按钮（生成临时 Web 链接，对方浏览器扫码/打开后上传）
- 左侧 / 底部 Tab：三页签 — **接收 / 发送 / 设置**

### 1.2 痛点

- 只能"传"不能"管"：手机向电脑"丢"一个文件后，无法浏览电脑上其他目录，更无法管理远端文件
- 没有跨盘导航：电脑上插了移动硬盘（`E:\`），手机端看不到，无法在手机上像本地文件 App 一样点开硬盘
- 缺少媒体回放：手机想看电脑里某段视频必须先下载整文件，不能边下边播
- 写入能力薄弱：只能"接收"；不能在手机上往电脑的某个目录新建文件夹、上传相册、清理旧文件

### 1.3 目标

把 LocalSend 从"局域网互传工具"升级为"个人局域网随身云盘"：

> 挂载端提供文件管理服务，移动端进行远程 CRUD 浏览

保留 LocalSend "无中心节点、端到端局域网直连、不限速、UI 清爽" 的基因；新增文件系统的远程可管理性。

### 1.4 非目标（Non-Goals）

- **不**取代专业 NAS / 同步盘：不要求跨广域网、版本历史、权限分组
- **不**引入中心索引服务：所有路径解析、缩略图、CRUD 全部由挂载端在本地完成
- **不**改造 LocalSend 现有的"接收 / 发送"主流程：仅在设备选择列表里增加"浏览驱动器"入口
- **不**承诺秒传 / 去重 / 加密分片：v1 范围以单连接流式 CRUD 为限

## 2. 角色与场景

### 2.1 角色

| 角色         | 设备                                 | 关键能力                                                                                |
|--------------|--------------------------------------|-----------------------------------------------------------------------------------------|
| **挂载端用户** | 在 macOS / Windows 上运行 LocalSend 的用户 | 1) 启动服务广播 2) 选择/勾选允许暴露的挂载点 3) 配对 PIN 4) 接受/拒绝移动端写操作        |
| **移动端用户** | 在 iOS / Android 上运行 LocalSend 的用户  | 1) 发现挂载端 2) 浏览目录/缩略图 3) 下载/上传/编辑文件 4) 媒体边下边播 5) 删除/移动        |

### 2.2 关键场景

| #   | 场景                                                                                                  | 期望结果                                                                                       |
|-----|-------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------|
| S1  | 用户在 iPhone 上点开 LocalSend，发现 Mac，**进入 Mac 的 `D:\Photos`**                                | 列表渲染缩略图，秒级响应；点击照片可直接全屏查看                                              |
| S2  | 用户在 iPhone 上点开 Mac 的 `E:\Movies\travel.mp4`                                                   | 视频播放器直接走 HTTP 206 Partial Content 边下边播，进度条可拖动                              |
| S3  | 用户在 iPhone 相册多选 50 张照片，希望传到 Mac 的 `D:\Photos\2026-09\`                                | 后台上传，断点续传，状态可见                                                                   |
| S4  | Mac 上新插入一块移动固态硬盘 `E:\`                                                                    | 移动端无需手动刷新，挂载列表自动多出该项                                                       |
| S5  | 用户在 iPhone 上重命名 Mac 上一个 `untitled.txt` 为 `note.txt`，并移动到 `D:\Work\`                 | 服务端 `rename` 系统调用，不消耗网络带宽                                                       |
| S6  | 用户在 iPhone 上批量删除 Mac 上的 `D:\tmp\*`                                                          | 服务端逐项 `delete`；如挂载端开启"移入回收站"选项，则走系统回收站                              |
| S7  | 用户在挂载端设置中**未勾选** `C:\`（系统盘）                                                          | 移动端永远看不到 `C:\`，越权请求被服务端 403 拒绝                                              |

## 3. 功能性需求

> 编号约定：**F-S-x** = 服务端需求；**F-C-x** = 移动端需求；**F-D-x** = 双方共需（发现 / 配对）

### 3.1 设备发现与配对（F-D）

| 编号   | 需求                                                                                                                                                                                  |
|--------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| F-D-1  | **保留现有组播/mDNS 发现**：挂载端继续以 `packages/core/src/multicast/` 的实现广播 v2.2 announce；移动端继续以现有 `IsolateSyncServerStateAction` 同步 server state 后开始扫描         |
| F-D-2  | **保留现有 PIN 配对 / 客户端证书 / 指纹识别**：不允许降级到无认证模式；TLS 强制客户端证书，关闭加密时仅放宽"网页下载"场景                                                        |
| F-D-3  | **入口扩展**：在移动端"接收方选择"列表中，每行除了"发送文件"外，增加「**浏览驱动器**」图标按钮，仅当该设备声明支持 `fs` capability（v2.3 协议扩展字段）时显示                          |
| F-D-4  | **能力声明（capability negotiation）**：挂载端在 announce / register payload 中新增可选字段 `capabilities: ["send","receive","fs"]`；移动端据此隐藏不适用入口                          |

### 3.2 挂载端（Server）功能性需求

#### 3.2.1 挂载点抽象

| 编号   | 需求                                                                                                                                                            |
|--------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------|
| F-S-1  | **挂载点枚举**：macOS 遍历 `/Volumes/*`；Windows 遍历 `D:`–`Z:` 可用盘符（排除 `C:` 系统盘默认）；Linux 遍历 `/media/$USER/*` 与 `/run/media/$USER/*`                  |
| F-S-2  | **白名单设置**：设置页新增「**可共享的存储设备**」多选列表；只有勾选项才会出现在移动端列表中。**默认全部未勾选**（用户主动选择）                                    |
| F-S-3  | **热插拔监听**：macOS 监听 `NSWorkspace.didMountNotification` / `didUnmountNotification`；Windows 通过 `WM_DEVICECHANGE` 消息（dart ffi 桥接）；Linux 通过 udev 事件 |
| F-S-4  | **挂载点状态广播**：热插拔事件后，向所有已配对移动端推送 `fs.root.changed` 事件，移动端无感刷新（不需要重新扫描）                                                  |

#### 3.2.2 REST API 路由

> 路径前缀统一 `/api/localsend/v2/fs`。所有请求**必须**经过现有 TLS + 客户端证书通道；以下不再重复 TLS 约定。

| 方法 / 路径                          | 功能                                   | 入参                              | 出参（精简）                                                                                                                                |
|--------------------------------------|----------------------------------------|-----------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------|
| `GET /roots`                         | 列出所有白名单挂载点                    | —                                 | `{ "roots": [ { "id":"D:", "label":"工作盘 (D:)", "totalBytes":..., "freeBytes":..., "filesystem":"exFAT" } ] }`                              |
| `GET /list?path=...&page=...&size=...` | 列出目录内容（分页）                  | `path`（必填，URL 编码）`page`（默认 0）`size`（默认 100，最大 200）`sort`（name/size/mtime，asc/desc） | `{ "entries":[ { "name":"IMG_0001.jpg", "isDir":false, "size":20971520, "mtime":..., "mime":"image/jpeg" } ], "total":1234, "hasMore":true }` |
| `POST /mkdir`                        | 新建目录                                | `{ "path":"D:/Photos/2026-09" }`   | `{ "path":"D:/Photos/2026-09" }`                                                                                                            |
| `POST /move`                         | 重命名或移动                            | `{ "from":"D:/a.txt", "to":"D:/Work/b.txt" }` | `{ "ok": true }`                                                                                                                            |
| `POST /delete`                       | 删除（支持批量，支持回收站）            | `{ "paths":[...], "recycle":true }` | `{ "deleted":["..."], "failed":[{ "path":"...", "reason":"..." }] }`                                                                       |
| `GET /download?path=...`             | 流式下载（必须支持 206）                 | `path`（必填）                    | `application/octet-stream`，`Accept-Ranges: bytes`                                                                                          |
| `POST /upload?path=...`              | 流式上传（multipart / chunked）         | `path`（目录） + body             | `{ "path":"D:/Photos/2026-09/IMG_0001.jpg", "size":... }`                                                                                   |
| `GET /thumbnail?path=...&w=...&h=...` | 服务端生成缩略图（避免拉原图）         | `path`、`w`（默认 128）、`h`（默认 128） | `image/webp`（小图）                                                                                                                        |
| `GET /stat?path=...`                 | 单文件元数据（断点续传、播放器探测）   | `path`                            | `{ "size":..., "mtime":..., "mime":..., "supportsRange":true }`                                                                            |

#### 3.2.3 安全沙箱

| 编号   | 需求                                                                                                                                                                                                                                                |
|--------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| F-S-5  | **绝对路径校验**：所有入参 `path` 必须在服务端用 `Directory(path).resolveSymbolicLinksSync()`（macOS/Linux）或 `GetFullPath`（Windows）解析为真实绝对路径；`..`、`符号链接跳出`、跨盘符一律 403                                                       |
| F-S-6  | **白名单兜底**：解析后的绝对路径必须以**某个白名单根**为前缀（大小写不敏感，Windows 大小写无关、macOS 用 `HFS+/APFS` case-aware 但比较时归一化）；否则 403                                                                                            |
| F-S-7  | **符号链接审计**：跨挂载点的 symlink 一律拒绝（避免软链到 `/etc` 等系统目录）                                                                                                                                                                       |
| F-S-8  | **写操作二次确认**：删除 / 移动 / 覆盖写 操作，移动端 UI 必须先弹确认；服务端同时要求请求体携带 `confirm: true` 字段，否则 400                                                                                                                       |
| F-S-9  | **请求体大小限制**：`upload` 单文件上限默认 10 GB，可由用户在设置中调整；超出返回 413                                                                                                                                                                |
| F-S-10 | **写权限回收**：用户在挂载端设置中**取消**某挂载点的勾选后，**正在进行的上传**立即被服务端 403 中止；不静默                                                                                                                                          |

#### 3.2.4 缩略图与媒体

| 编号   | 需求                                                                                                                                                                                                                          |
|--------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| F-S-11 | **服务端缩略图**：在 Rust 端使用 `image` crate 解码 JPEG/PNG/WebP/HEIC（macOS）/ BMP/GIF，缩放至请求尺寸，编码为 WebP（fallback JPEG）。EXIF 方向自动校正                                                                  |
| F-S-12 | **视频缩略图**：v1 范围仅"首帧抽帧"或"返回占位 SVG"；v2 引入 ffmpeg-sidecar（**v2 再说，v1 用占位图**）                                                                                                                         |
| F-S-13 | **HTTP Range 支持**：`/download` 必须遵守 `Range: bytes=` 头返回 206；播放器拖动进度条依赖此能力                                                                                                                                |

### 3.3 移动端（Client）功能性需求

#### 3.3.1 入口与导航

| 编号   | 需求                                                                                                                                                            |
|--------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------|
| F-C-1  | **设备列表新入口**：在原本"接收方列表"每行右侧追加"浏览驱动器"图标（macOS 在侧栏 / iOS 在底部 Tab 切换后从发送页/主页进入，按平台 UX 一致性为准）                |
| F-C-2  | **面包屑路径导航**：进入挂载端后，顶部展示 `挂载点 / 一级 / 二级 / ...` 路径，可点击任一级跳转                                                              |
| F-C-3  | **多视图切换**：列表 / 网格 两种视图，状态持久化（按挂载端分组）                                                                                              |
| F-C-4  | **排序与筛选**：名称 / 大小 / 修改时间升序降序；按类型筛选（图片 / 视频 / 文档 / 全部）                                                                       |

#### 3.3.2 CRUD 操作

| 编号   | 需求                                                                                                                                                                                                                                  |
|--------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| F-C-5  | **新建文件夹**：在当前目录长按/菜单触发，弹出命名对话框，成功后列表无感刷新                                                                                                                                                          |
| F-C-6  | **上传**：移动端从相册 / 文件选择器多选后，"分享到"或"保存到"当前目录。**后台并发上传**（2~4 并发），支持取消 / 断点续传（`Content-Range`）                                                                                       |
| F-C-7  | **下载**：点击文件后弹底部 sheet：保存到相册 / 保存到 Files / 仅预览；大文件走后台                                                                                                                                              |
| F-C-8  | **重命名 / 移动**：长按 → 菜单 → 重命名 / 移动。移动 = 选择目标目录，提交时一次性 POST `/move`（**服务端 rename 系统调用，不上传文件内容**）                                                                                       |
| F-C-9  | **删除**：长按 → 多选 → 删除；弹二次确认；可选择"移入回收站"（如挂载端开启该能力）                                                                                                                                              |
| F-C-10 | **缩略图懒加载**：列表/网格仅在视口内请求 `/thumbnail?w=128&h=128`；下拉刷新；不命中时回退到类型图标                                                                                                                                |
| F-C-11 | **媒体预览**：图片 = 全屏相册式横滑；视频 / 音频 = `video_player` / `just_audio` 走 `/download` 的 Range 协议边下边播                                                                                                                |
| F-C-12 | **大目录分页**：单次请求 100 项；上拉加载更多（`hasMore`）                                                                                                                                                                          |

#### 3.3.3 实时性

| 编号   | 需求                                                                                                                                                            |
|--------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------|
| F-C-13 | **挂载点变化推送**：服务端推送 `fs.root.changed` 事件，移动端立即更新左侧/顶部挂载点列表，不要求重新握手                                                            |
| F-C-14 | **同一挂载端多客户端**：两台手机同时连一台 Mac，应能各自浏览、上传，A 的删除不影响 B 的视图（除非两者都在编辑同一目录，需要乐观锁，**v1 暂不支持并发写同一目录**）|

## 4. 非功能性需求

### 4.1 安全

| 编号    | 指标                                                                                                                                  |
|---------|---------------------------------------------------------------------------------------------------------------------------------------|
| N-SEC-1 | **零信任路径解析**：F-S-5、F-S-6、F-S-7 三道防线必须全部命中；任何越权返回 403 且写入审计日志（tracing 字段 `event="fs.path.denied"`） |
| N-SEC-2 | **默认拒绝**：未在白名单中的挂载点对移动端不可见、不可访问；包括 `127.0.0.1` / `localhost` 自身的扫描也必须经过白名单                    |
| N-SEC-3 | **TLS 强制**：所有 `/api/localsend/v2/fs/*` 端点必须 `https://`；明文 HTTP 模式下整个 fs 子系统**不挂载**（启动时 panic 并打 ERROR 日志）|
| N-SEC-4 | **PIN 复用**：复用现有 LocalSend 接收 PIN；不允许为 fs 再设独立 PIN 以减少用户认知负担                                              |
| N-SEC-5 | **审计日志**：所有写操作记录 `who（fingerprint）、what（path）、when、result`；保留 7 天供用户自查                                    |

### 4.2 性能

| 编号    | 指标                                                                                                                                                  |
|---------|-------------------------------------------------------------------------------------------------------------------------------------------------------|
| N-PER-1 | 列出 1000 项目录的接口 P95 ≤ 300 ms（本地 SSD，常规 home dir）                                                                                       |
| N-PER-2 | 缩略图接口 P95 ≤ 150 ms（128×128，从原图 resize）                                                                                                    |
| N-PER-3 | 单连接上传速度 ≥ 局域网物理速率的 80%（5 GHz Wi-Fi 期望 ≥ 200 Mbps）                                                                                 |
| N-PER-4 | 大目录分屏首屏 ≤ 1 s 渲染完成（含缩略图占位）；后续上拉 P95 ≤ 500 ms                                                                                  |
| N-PER-5 | 移动端 UI 不阻塞：所有网络 IO 走 `packages/localsend_isolates/` 已有的 isolate 通道，主线程不掉帧（≥ 55 fps 滚动）                                 |

### 4.3 可靠性

| 编号    | 指标                                                                                                                                              |
|---------|---------------------------------------------------------------------------------------------------------------------------------------------------|
| N-REL-1 | 上传中断（应用被杀 / Wi-Fi 断开）后，重新打开能**断点续传**（基于 `Content-Range` + `If-Match` Etag / `Last-Modified` 校验）                       |
| N-REL-2 | 移动端删除文件后，挂载端如果在外部也修改了同名文件，移动端下次进入该目录必须拿到最新 mtime，不能展示陈旧列表                                          |
| N-REL-3 | 服务端在热插拔事件导致挂载点消失时，**正在进行的 IO 立即失败**并向移动端推送 `fs.entry.removed` 事件，避免悬空句柄                                    |

### 4.4 可用性

| 编号    | 指标                                                                                            |
|---------|-------------------------------------------------------------------------------------------------|
| N-UX-1  | 关键错误必须本地化为已有 i18n key（zh-CN / en 必中）                                            |
| N-UX-2  | 在 iOS 17+ 暗色模式下保持截图中深色风格（青色 `#0FB6A6` 系品牌色沿用）                          |
| N-UX-3  | macOS 侧栏与 iOS 底部 Tab 的三页签顺序保持 **接收 / 发送 / 设置**                                |

## 6. 协议与 API 摘要

> 实现细节以技术方案为准；此处只钉接口形态。

### 6.1 能力声明（v2.3 协议扩展，**向后兼容**）

挂载端 announce / register payload 中追加字段：

```json
{
  "alias": "常平zego-mac",
  "version": "2.3.0",
  "deviceModel": "...",
  "deviceType": "mobile|desktop|web|headless",
  "fingerprint": "AB12...",
  "port": 53317,
  "protocol": "https",
  "download": true,
  "announce": true,
  "capabilities": ["send", "receive", "fs"]
}
```

- `capabilities` 缺省时按 `["send","receive"]` 处理
- 移动端仅当 `fs ∈ capabilities` 时才显示"浏览驱动器"入口

### 6.2 服务推送事件（Server-Sent / 长连接）

复用现有 `ServerEventV2` 通道，**不**开新 side channel；新增 variant：

```rust
enum ServerEventV2 {
    // ...existing...
    FsRootsChanged { roots: Vec<FsRoot> },
    FsEntryRemoved { paths: Vec<String> },
    FsUploadProgress { sessionId: String, transferred: u64, total: u64 },
}
```

## 9. 风险与缓解

| 风险                                                                  | 影响                                            | 缓解                                                                                                            |
|-----------------------------------------------------------------------|-------------------------------------------------|-----------------------------------------------------------------------------------------------------------------|
| 路径解析在 Windows / macOS 行为不一致（大小写、符号链接、盘符大小写） | 越权或白名单误判                                | 集中抽象 `FsPath` 工具类，单元测试覆盖 30+ case；CI 多平台跑同一 fuzz seed                                        |
| 移动端断点续传跨协议版本兼容                                          | 大文件传输失败                                  | 上传使用 `Content-Range` + 自定义 ETag（mtime+size 的 hash）；不依赖 LocalSend 协议版本号                        |
| 服务端缩略图对 HEIC / RAW 性能差                                     | 列表卡顿                                       | v1 跳过 HEIC/RAW（fallback 图标）；v2 引入 macOS 私有 framework 或 ImageMagick sidecar                          |
| F-Droid 可复现构建对生成代码（缩略图 cache）影响                       | 每次构建产物不一致                              | 缩略图**不**持久化到 `target/`，全部由 Rust crate 在请求时生成                                                  |
| v2.3 capability 字段让老客户端 panic                                  | 兼容问题                                       | 服务端 JSON 解析允许 `capabilities` 缺省；老客户端按 `["send","receive"]` 处理                                  |
| iOS 后台上传被系统杀                                                  | 任务丢失                                        | 用 `flutter_foreground_task`（已在 `packages/localsend_isolates/pubspec.yaml` 中声明）跑上传 worker              |
